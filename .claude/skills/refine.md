# /refine — 笔记打磨

读取用户放在 `drafts/` 中的不完善笔记，通过 LLM 审查和对话迭代打磨至可归档状态。

## 工作流

### 1. 发现草稿
- 若用户指定文件，直接读取
- 若未指定，列出 `drafts/` 下所有文件，供用户选择要打磨的笔记

### 2. 阅读分析
- 完整阅读草稿内容
- 从以下维度分析：
  - **完整性** — 是否遗漏关键概念、步骤、前提条件
  - **准确性** — 是否有事实错误、过时信息、逻辑矛盾
  - **清晰度** — 表述是否模糊、术语是否定义、结构是否混乱
  - **关联性** — 与 Wiki 已有知识是否存在可链接的点（标注 `[[wikilink]]` 建议）

### 3. 输出审查意见
- 列出发现的问题，按严重程度排列：
  - 错误（需立即修正）
  - 缺失（需补充的缺口）
  - 模糊（需要澄清）
  - 建议（可改进之处）
- 每条意见附具体位置引用和建议修改方向

### 4. 讨论迭代
- 逐条与用户讨论审查意见
- 用户对每一条可以选择：接受修改 / 忽略 / 亲自补充
- 根据讨论结果更新草稿

### 5. 归档判定
- 打磨完成后，与用户讨论草案的去向：
  - **→ `wiki/concepts/`** — 概念性知识内容
  - **→ `wiki/entities/`** — 实体性知识内容
  - **→ `wiki/comparisons/`** — 对比分析内容
  - **→ `raw/`** — 原始参考性质，成为不可变来源
  - **→ 保留 `drafts/`** — 仍需继续打磨
  - **→ 删除** — 内容已过时或不再需要
- 若归档到 `wiki/` 或 `raw/`，按 `/ingest` 的子流程更新 `wiki/index.md` 和 `wiki/log.md`

### 6. 标记状态
- 在草稿 frontmatter 中更新 `status` 字段：
  - `draft` → `refined` → `archived`
- 若归档，在 frontmatter 中添加 `archived-to` 字段指向目标路径

## 失败处理
- drafts/ 为空 → 告知用户并给出笔记写作建议（参考 CLAUDE.md 的格式规范）
- 用户不参与讨论 → 仅输出审查意见，不做任何修改
- 草稿内容过于零散 → 建议用户先补充核心内容再打磨，不强行整理

## 输出
- 审查意见清单
- 修改后的草稿（若经讨论）
- 归档去向及操作摘要
