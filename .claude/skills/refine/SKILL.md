# /refine — 笔记打磨

读取用户放在 `drafts/` 中的不完善笔记，通过 LLM 审查和对话迭代打磨至可归档状态。

## 工作流

### 1. 发现草稿
- 若用户指定文件，直接读取
- 若未指定，列出 `drafts/` 下所有文件，供用户选择要打磨的笔记

### 2. 阅读分析
- 完整阅读草稿内容
- 从以下维度分析：
  - **完整性** — 是否遗漏关键概念、步骤、前提条件
  - **准确性** — 是否有事实错误、过时信息、逻辑矛盾
  - **清晰度** — 表述是否模糊、术语是否定义、结构是否混乱
  - **关联性** — 与 Wiki 已有知识是否存在可链接的点（标注 `[[wikilink]]` 建议）

### 3. 输出审查意见
- 列出发现的问题，按严重程度排列：
  - 错误（需立即修正）
  - 缺失（需补充的缺口）
  - 模糊（需要澄清）
  - 建议（可改进之处）
- 每条意见附具体位置引用和建议修改方向

### 4. 讨论迭代
- 逐条与用户讨论审查意见
- 用户对每一条可以选择：接受修改 / 忽略 / 亲自补充
- 根据讨论结果更新草稿

### 5. 归档到 raw/（领域门控）

#### 5a. 提议目标领域
- 根据笔记主题，映射到 `raw/` 下最合适的现有子目录
- 参考 CLAUDE.md 目录树确认领域存在
- 若存在明确的归属 → 与用户确认后直接归档
- 若映射不明确（多个可能领域）→ 列出选项供用户决定
- 若**无合适领域** → 进入 5b

#### 5b. 领域扩展提案（仅在无合适领域时触发）
- 向用户报告：「当前没有现有领域适合此内容」
- 按 CLAUDE.md `raw/ 领域扩展规则` 验证提案：
  - **命名规范**：kebab-case、单数/复数规则、无缩写
  - **深度限制**：最大 2 层
  - **创建标准**：3+ 源文件或预期、正交性、适当抽象层级
- 解释为何不适合现有领域，指出与最接近领域的差异
- 询问用户：「是否创建新领域 `raw/<domain>/<subdomain>/`？还是你希望指定其他位置？」

#### 5c. 执行（按用户决策）
- **用户批准创建** → 创建目录，归档文件，进入 5d
- **用户拒绝，指定替代位置** → 使用用户指定的现有目录归档
- **用户想亲自处理** → 停止，告知用户应：
  1. 创建 raw/ 目录
  2. 将文件移入
  3. 更新 CLAUDE.md 目录树
  4. 重新运行 `/refine` 或直接 `/ingest`

#### 5d. CLAUDE.md 同步提醒
- 若创建了新领域，提醒用户：「CLAUDE.md 目录树需要同步更新以反映新领域 `raw/<domain>/<subdomain>/`」
- `/lint` 后续会检测 CLAUDE.md 与实际目录的不匹配

#### 5e. 触发摄取
- raw/ 写入完成后，**立即执行 `/ingest`** 处理该 raw 文件：
  - 按照 ingest 标准流程：阅读 → 讨论 → 生成实体/概念/对比分析页面
  - 更新 `wiki/index.md` 和 `wiki/log.md`

### 6. 标记状态
- 在草稿 frontmatter 中更新 `status` 字段：
  - `draft` → `refined` → `archived`
- 添加 `archived-to` 字段指向 raw/ 目标路径

## 失败处理
- drafts/ 为空 → 告知用户并给出笔记写作建议（参考 CLAUDE.md 的格式规范）
- 用户不参与讨论 → 仅输出审查意见，不做任何修改
- 草稿内容过于零散 → 建议用户先补充核心内容再打磨，不强行整理

## 输出
- 审查意见清单
- 修改后的草稿（若经讨论）
- raw/ 归档路径及 ingest 执行摘要（创建的实体/概念/对比分析页面列表）
