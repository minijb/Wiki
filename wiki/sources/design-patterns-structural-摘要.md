# 结构型设计模式 — 摘要

来源：`raw/cs/design-patterns/structural-patterns.md`

## 概述

七种 GoF 结构型模式的完整指南，涵盖适配器、桥接、组合、装饰、外观、享元、代理。每个模式包含 UML 类图（Mermaid）、完整 C# 代码示例、参与者分析、适用场景（含何时不使用）、变体、常见反模式、以及与其他模式的关系。末尾提供模式关系总览图。

## 各模式要点

- **适配器**：对象适配器（组合）是 C# 唯一可行方式——将 `SquarePeg` 适配为 `IRoundPeg`。`System.Data.Common` 的 `DbDataAdapter` 是 .NET 经典适配器。与桥接的区别——适配器是**事后补救**，桥接是**预先设计**。**变体**：对象适配器、类适配器（C# 不支持）、双向适配器

- **桥接**：将抽象（遥控器）与实现（设备）分离，各自独立变化。m 个抽象 × n 个实现 = m+n 个类（非 m×n）。`Stream` + `TextReader`/`TextWriter` 是 .NET 桥接的经典示例。可与抽象工厂结合封装配对关系。**避坑**：过度桥接（只有一个实现）、抽象泄露

- **组合**：递归树形结构，叶节点和组合节点共享接口。设计权衡——透明性（`Add` 在 Component 中，叶节点抛异常）vs 安全性（`Add` 仅在 Composite 中）。**变体**：透明组合、安全组合、带父引用的组合。**避坑**：Component 接口过重、循环引用导致栈溢出、客户端类型判断破坏透明性

- **装饰**：与代理的类图几乎相同但意图不同——**装饰添加行为**，**代理控制访问**。ASP.NET Core 中间件管道、`Stream` 的 `CryptoStream`/`GZipStream` 是经典装饰链。运行时可根据配置组装不同装饰栈。**避坑**：装饰器顺序依赖、装饰器泄露（客户端持有具体装饰器引用）、接口过重导致大量转发方法

- **外观**：为复杂子系统提供简化入口。单向的（客户端→子系统），不禁止客户端直接访问子系统类。`VideoConverter` 封装多个编码/解码类。与中介者的区别——外观是**单向简化**，中介者是**双向协调**。**避坑**：上帝外观、外观绑定（硬编码依赖具体外观类）、忽略底层能力

- **享元**：内在状态（不变、可共享）vs 外在状态（随情景变化）。通过工厂缓存共享对象。内在状态必须不可变——setter 或公共可变字段会导致难以追踪的副作用。C# 中 `string.Intern()` 和 `Brushes.Red` 是享元的内置实现。**避坑**：外在状态计算成本高、享元工厂内存泄露、线程不安全修改

- **代理**：六种变体——虚拟代理（`Lazy<T>`）、保护代理（Authorization proxy）、远程代理（gRPC stub）、日志代理（Logging wrapper）、缓存代理（`IMemoryCache` 包装）、智能引用（`WeakReference`）。实现与服务对象相同的接口，客户端无法区分代理和真实对象。**避坑**：代理链过长、代理行为与真实对象不一致（违反里氏替换）、代理职责混杂

## 关键对比

| 对比组 | 核心差异 |
|--------|----------|
| 适配器 vs 桥接 | 事后补救 vs 预先设计 |
| 装饰 vs 代理 | 添加行为 vs 控制访问 |
| 外观 vs 中介者 | 单向简化 vs 双向协调 |
| 适配器 vs 外观 | 单个对象接口转换 vs 整个子系统简化入口 |
