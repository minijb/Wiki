# 游戏帧同步技术

## 来源

`raw/gamedev/networking/unity-frame-sync.md` — 帧同步（Lockstep）完整技术体系：从算法原理、工程实践到王者荣耀案例分析

## 要点

1. **帧同步核心思想** — 客户端仅同步操作指令（input/command），各客户端独立执行相同确定性逻辑；视觉表现与逻辑计算解耦是理解帧同步的第一原则
2. **严格帧锁定** — 服务器收集所有客户端操作后才广播下一关键帧，最慢客户端拖慢所有人，公网环境下几乎不可用
3. **乐观帧锁定** — 服务器按固定间隔（20~50fps）广播，未上报操作视为空输入；指令缓存采用轮询执行策略保证公平性，可根据网络质量自适应调整帧率
4. **影子跟随算法** — 由 Dead Reckoning 发展而来：实体连续平滑地追赶"影子"（服务器下发的跳变状态），状态数据格式为 `ID + 坐标 + 方向 + 速度 + 帧号`
5. **相位滞后与惯性** — 实体与影子保持固定距离避免"冲过头再拉回"；惯性方案（加速/减速平滑）可替代相位滞后，对玩家手感更友好但实现更复杂
6. **Counter-Strike 与 Mario Kart** — CS 使用惯性移动 + 客户端判定射击 + 关键状态缓存；Mario Kart 使用延迟爆炸道具 + 服务器权威/客户端预测混合模式
7. **KCP 可靠传输协议** — 基于 UDP 的算法层，提供快速/可靠/有序传输；可配置 RTO 策略、选择性重传、`NoDelay`/`WndSize`/`SetMtu` 等参数按游戏场景调优
8. **KCPSession C# 实现** — `UdpClient` + `IKcpCallback` 回调绑定 + 独立接收线程 + `kcp.Update()` 主循环驱动状态机，配合 `Task.Run` 异步运行
9. **预测回滚** — 双缓冲区（`LBuffer` + `SBuffer`）架构，客户端预测执行后若与服务器不一致则回滚重算；代码生成方案是回滚实现的最佳实践
10. **王者荣耀案例** — 66ms 逻辑帧间隔（~15fps）、`match_frames` 存储全帧操作以支持录像回放和断线重连、`sync_frameid` + `logic_pos` 统一时基、丢包补发与过时帧丢弃
11. **确定性黄金法则** — 禁止使用 `float`（必须用定点数 `Fix64`）、禁止多线程（必须单线程确定顺序执行）；确定性 PRNG、稳定遍历顺序、整数物理引擎（`bepuphysics1int`）、确定性寻路（`DotRecast`）
