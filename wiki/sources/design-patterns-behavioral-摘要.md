# 行为型设计模式 — 摘要

来源：`raw/cs/design-patterns/behavioral-patterns.md`

## 概述

十种 GoF 行为型模式的完整指南，涵盖责任链、命令、迭代器、中介者、备忘录、观察者、状态、策略、模板方法、访问者。每个模式包含 UML 类图（Mermaid）、完整 C# 代码示例、参与者分析、适用场景（含何时不使用）、变体、常见反模式、以及与其他模式的关系。末尾提供模式关系总览图和关键对比总结表。

## 各模式要点

- **责任链**：请求沿链传递直到被处理。两种变体——纯责任链（一个处理者处理即停）和不纯责任链（每个都执行，如 ASP.NET 中间件管道）。C# 实现支持流畅链式组装。**避坑**：链断裂（忘记调用 `_next`）、循环链、链过长

- **命令**：将请求封装为对象——支持撤销/重做、任务队列、宏命令。命令执行前用备忘录保存状态实现完整撤销。与策略的区别——命令封装**请求及其参数**，策略封装**可互换算法**。**避坑**：命令膨胀（每个操作一个类）、撤销逻辑不一致、命令持有过多状态

- **迭代器**：C# 语言内置支持——`IEnumerable<T>` + `yield return`。编译器自动生成状态机，无需手写迭代器类。**变体**：外部迭代器、内部迭代器、双向迭代器、随机访问迭代器。**避坑**：并发修改异常、迭代器延长集合生命周期、滥用延迟查询

- **中介者**：组件通过中介者通信，解除多对多耦合。与外观的区别——外观是**单向简化**，中介者是**多对多双向协调**。可与观察者组合——中介者作为观察者处理事件后协调。C# 社区推荐 MediatR 库而非手写。**避坑**：上帝中介者、循环依赖、过度中介

- **备忘录**：原发器自行创建快照，备忘录对外不透明——仅原发器可读取。结合命令模式实现撤销——命令执行前保存备忘录，撤销时恢复。C# 中 `record` 类型是天然的快照载体。**避坑**：备忘录泄露（外部修改）、内存膨胀（大量完整快照）、忘记在 `Execute` 前保存

- **观察者**：C# 原生通过 `event` 关键字支持。`IObservable<T>` / `IObserver<T>`（Rx.NET）提供标准化的可订阅流。**推送模式**（Subject 推送全部数据）vs **拉取模式**（Observer 自行获取）。优先用 `event` 替代手动维护观察者列表。**避坑**：内存泄露（忘记注销）、通知风暴（级联更新）、循环通知

- **状态**：有限状态机实现——每个状态封装行为和转换规则。与策略的区别——状态**知道自己何时转换为下一状态**，策略由**外部切换**。可与享元结合共享无状态的状态对象。C# 编译器的 `IAsyncStateMachine` 是状态模式的应用。**避坑**：状态对象持有过多上下文数据、转换逻辑分散、状态爆炸

- **策略**：算法族的可互换封装——支付策略、压缩算法、排序策略。与命令的核心区别在于意图而非结构。与模板方法对比——策略用**组合**（运行时切换），模板方法用**继承**（编译时确定）。C# 中 `Func<>`/`Action<>` 委托可替代简单策略。**避坑**：策略过多（类爆炸）、策略泄露（客户端判断具体类型）、策略膨胀（接口方法太多）

- **模板方法**：好莱坞原则——"Don't call us, we'll call you"。**三种步骤**：抽象步骤（子类必须实现）、默认步骤（可选重写）、钩子方法（空实现扩展点）。与策略互补——模板方法定义骨架，策略替换步骤算法。常被框架用于定义生命周期方法。**避坑**：模板方法过大、滥用钩子、遗忘 `base` 调用

- **访问者**：双分派机制——`Accept(visitor)` → `visitor.VisitXxx(this)`。适用于元素层次**稳定**但需**频繁添加新操作**的场景。访问者可跨元素累积状态（如 `TotalArea`）。不适用于元素层次频繁变化的场景——每次新增元素都要修改所有访问者。**避坑**：过度使用（2-3 种元素类型时不需要）、元素泄露（访问者转型获取内部状态）、访问者膨胀、忘记更新所有访问者

## 关键对比总结

| 对比组 | 核心差异 |
|--------|----------|
| 策略 vs 状态 | 外部切换 vs 内部驱动转换（类图相同，意图不同） |
| 策略 vs 命令 | 封装可互换算法 vs 封装请求及其参数 |
| 模板方法 vs 策略 | 继承（编译时）vs 组合（运行时） |
| 观察者 vs 中介者 | 一对多广播 vs 集中式多对多协调 |
| 命令 vs 备忘录 | 封装操作 vs 保存状态（常组合使用） |
| 责任链 vs 装饰 | 可提前终止 vs 每个都执行 |
