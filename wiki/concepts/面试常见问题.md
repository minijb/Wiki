## C# 基础

### 装箱和拆箱的原理是什么？

- **装箱**：将值类型转换为 `object` 类型。过程在托管堆分配内存，复制值，返回堆中新分配对象的地址。
- **拆箱**：从 `object` 类型显式转回值类型，先检查引用是否为装箱的值类型，再复制堆上数据。

> [!tip] 避免装箱的方法
> - `struct` 重载 `ToString()`、`GetType()` 等方法——否则调用时会先装箱。
> - 使用泛型（`List<int>` 代替 `ArrayList`）避免装箱拆箱。
> - 值类型通过统一接口操作时会触发装箱。

参考：[[CSharp值类型性能]]

### C# 多态是如何实现的？

- **静态多态（编译时）**：函数重载。
- **动态多态（运行时）**：虚方法（`virtual`/`override`）、抽象类（`abstract`）、接口（`interface`）。

### `const` 和 `readonly` 的区别

| 特性 | `const` | `readonly` |
|------|---------|------------|
| 赋值时机 | 声明时必须赋值 | 声明时或构造函数中赋值 |
| 作用域 | 类字段 + 局部变量 | 只能是类字段 |
| 性质 | 编译时常量 | 运行时常量 |
| 静态 | 默认是静态的 | 需要 `static` 显式声明 |
| 修饰类型 | 只能 `string`/`null`/基本类型 | 任意类型 |

### `struct` 和 `class` 的区别

- `struct` 是**值类型**，分配在栈上（或作为对象成员时内嵌）——参见 [[CSharp值类型性能]]。
- `class` 是**引用类型**，分配在托管堆上。
- `struct` 不能继承（隐式 `sealed`），不能有无参构造函数。

### `String` 和 `StringBuilder` 的区别

- `String`：不可变字符串常量，线程安全。每次修改都会创建新对象。
- `StringBuilder`：可变字符串变量，非线程安全。频繁拼接时性能远优于 `String`。
- `string` 类是 `sealed` 的，不能被继承。

### `sealed` 关键字的作用

1. 用于 `class`：不能被继承，不能与 `abstract` 同时使用。
2. 用于方法和属性：不能被重写，必须和 `override` 一起使用。

### `for` 和 `foreach` 的选择

- 长度固定：使用 `for`。
- 长度不固定：使用 `foreach` 遍历集合。但 `foreach` 在迭代过程中会释放用完的资源，可能造成额外 GC。

### `int?` 可空类型

`int?` 是通过将 `int` 装箱为引用类型实现的，本质是 `Nullable<int>`。

### 闭包的原理

Lambda 表达式可以捕获外部变量形成闭包。编译器生成一个带有捕获变量字段的匿名类，Lambda 表达式体成为该类的方法。

### `GetHashCode` 与 `Equals` 的关系

1. 对象相等（`a.Equals(b)` 为 `true`）→ `GetHashCode()` 必定相同。
2. `GetHashCode()` 相同 → 两个对象不一定相等（哈希碰撞）。

### `Sleep` 和 `Wait` 的区别

- `Thread.Sleep`：挂起当前线程指定时间，不释放锁。
- `Wait`（`Monitor.Wait`）：释放对象上的锁并阻塞当前线程，直到重新获得锁。

### 构造函数

构造函数不能继承，因此不能被重写，但可以重载。

### 静态成员

1. 类第一次加载到内存时创建，通过类访问。
2. 非静态成员在对象实例化时创建，通过对象访问。
3. 静态方法不能直接使用非静态成员。
4. 静态成员属于类，不属于对象。

## C# 多线程与异步

参考：[[CSharp并发模型]]、[[CSharp异步模型]]

### 线程基础操作的代码示例

```csharp
var thread1 = new Thread(Increment);
thread1.Start();
thread1.Join();              // 等待线程结束
thread1.Interrupt();         // 中断线程，在线程中抛出异常
// 如果 while(true) 循环，需要添加 Thread.Sleep() 配合中断

Interlocked.Increment(ref count); // 原子操作

Parallel.ForEach(items, item => Process(item));
PLINQ: source.AsParallel().AsOrdered();
```

### 线程安全机制有哪些？

**锁机制：**
- `lock`（本质是 `Monitor`）
- `Mutex`：可跨进程共享，`m.WaitOne()` / `m.ReleaseMutex()`
- `Semaphore`：信号量，可释放多个资源。`new Semaphore(3, 3)` 表示初始和最大资源数均为 3
- `ReaderWriterLock`/`ReaderWriterLockSlim`：读写锁
- `WaitHandle`：`ManualResetEvent`、`AutoResetEvent`

**轻量型（推荐在 `async` 上下文中使用）：**
- `SemaphoreSlim`
- `ManualResetEventSlim`
- `ReaderWriterLockSlim`

**内置轮子：**
- 线程安全的单例：`Lazy<T>`
- 线程安全的集合：`ConcurrentBag<T>`、`ConcurrentStack<T>`、`ConcurrentQueue<T>`、`ConcurrentDictionary<TKey, TValue>`
- 阻塞集合：`BlockingCollection<T>`
- 通道：`Channel<T>`
- 原子操作：`Interlocked`
- 周期任务：`PeriodicTimer`

### 多线程 vs 异步编程

| 特性 | 多线程 | 异步 |
|------|--------|------|
| 适用场景 | CPU 密集操作、长期运行的任务 | IO 密集操作、短小任务 |
| 资源开销 | 创建销毁开销大，不易传参返回 | 避免线程阻塞，提高响应能力 |
| 线程模型 | 可以多线程 | 可以单线程也可以多线程 |

> [!note] 关键认知
> 异步编程的核心是**不阻塞**，不一定要使用多线程；可以使用时间片轮转。

### `async`/`await` 的运行机制

```csharp
async Task Main()
{
    await FooAsync();
}

Task FooAsync()
{
    return Task.Delay(200);
}
```

- `async` 关键字的作用：使方法内部可以使用 `await`。不是一定要加 `async`——如果方法只返回 `Task`，可以不写 `async`。
- `await` 的作用：等待异步任务结束并返回结果。`await` 会暂时释放当前线程，执行其他工作，不阻塞。
- 异步编程本质是一个**状态机**，使用 `MoveNext` 切换状态。
- `async void` 也会生成状态机，但**无法处理异常**，真实用途仅限于异步事件注册。

### 阻塞方式分类

- `Task.Wait` / `Task.Result`：如果任务未完成则阻塞当前线程，容易造成死锁。
- `task.GetAwaiter().GetResult()`：同样是阻塞，但异常不包装为 `AggregateException`。
- IO 同步操作、耗时操作。

### `ConfigureAwait(false)`

`ConfigureAwait(false)` 表示不在原同步上下文（如 UI 线程）上继续执行，避免死锁，提高性能。

### `TaskScheduler`

可以控制 `Task` 的上下文、优先级执行状态、调度方式。

### 创建异步任务

```csharp
Task.Run(() => SyncMethod());           // 在线程池线程上执行

Task.Factory.StartNew(() => ...,        // 更完备的 Run，支持 TaskCreationOptions.LongRunning
    TaskCreationOptions.LongRunning);

new Task(() => ...).Start();            // 较少使用
```

### 同时开启多个异步任务

- 避免在 `for` 循环中使用 `await`。
- 使用 `Task.WhenAll()` / `Task.WhenAny()`：

```csharp
await Task.WhenAll(tasks);
var outputs = tasks.Select(x => x.Result).ToArray();
```

### 取消异步任务

`CancellationTokenSource` + `CancellationToken`：

```csharp
var cts = new CancellationTokenSource();
var token = cts.Token;

try
{
    var task = Task.Delay(10000, token);
    Thread.Sleep(1000);
    cts.Cancel();                      // 取消
    await task;
}
catch (TaskCanceledException) { }
finally { cts.Dispose(); }
```

快捷方式：
- `cts.CancelAfter(3000)`：3 秒后自动取消。
- `new CancellationTokenSource(TimeSpan.FromSeconds(3))` 或 `new CancellationTokenSource(3000)`：构造时设定超时。
- 所有内置 `async` 方法都有接受 `CancellationToken` 的重载。

**在同步方法中实现取消效果：**

```csharp
return Task.Run(() =>
{
    if (cts.IsCancellationRequested)
        cts.ThrowIfCancellationRequested();

    while (true)
    {
        if (cts.IsCancellationRequested)
            cts.ThrowIfCancellationRequested();
    }
});
```

**取消后续处理：**

```csharp
token.Register(() => Console.WriteLine("善后工作"));
// 可以多次注册，按顺序执行
```

**不推荐**：`return Task.FromCanceled<T>(cts)` 提前退出（配合 `Task.IsCanceled` 使用）。

### `TaskCanceledException` vs `OperationCanceledException`

`TaskCanceledException` 继承自 `OperationCanceledException`。
- `ThrowIfCancellationRequested` 抛出 `OperationCanceledException`。
- `ThrowIfCancellationRequested` 既可用于异步也可用于同步方法。

> [!warning] 注意
> `Task.Run` 可以传入 `CancellationToken`，但使用的不是传入的那个，而是外部的——因为传入的是回调函数，仅用于提前判断是否取消。

## Unity 基础

参考：[[Unity脚本架构]]、[[Unity性能优化]]、[[Unity资源管理]]

### 四元数（Quaternion）与欧拉角

**四元数**用于表示旋转，避免万向锁（Gimbal Lock）：

1. 避免万向锁。
2. 只需一个四维四元数即可执行绕任意轴的旋转。
3. 可提供平滑的球面线性插值（Slerp）。

**欧拉角**：绕 X、Y、Z 三个轴的旋转角度。
- 静态欧拉角：绕世界坐标系三个轴旋转。
- 动态欧拉角：绕物体自身坐标系三个轴旋转。
- Unity 3D 欧拉角旋转顺序（父子关系）：Y → X → Z。

### Unity 生命周期

执行顺序：
1. `Awake`：脚本实例创建时调用
2. `OnEnable`：对象激活时调用
3. `Start`：第一次 `Update` 执行前调用
4. `FixedUpdate`：固定物理时间间隔调用
5. `Update`：每帧调用
6. `LateUpdate`：每帧 `Update` 结束后调用（常用于相机跟随）
7. `OnGUI`：处理 GUI 事件
8. `OnDisable`：对象非激活时调用
9. `OnDestroy`：对象销毁时调用

### 协程（Coroutine）

实现原理是**迭代器**。`yield return` 将程序挂起，走的是单线程。挂起后在 `Update` 之后、`LateUpdate` 之前恢复执行。

> [!warning] 协程与 SetActive
> `enabled` 对协程没有影响；但 `SetActive(false)` 会使已启动的协程完全停止。

**yield return 类型：**
- `WaitForSeconds`：受 `timeScale` 影响
- `WaitForSecondsRealTime`：不受 `timeScale` 影响
- `WaitForEndOfFrame`：当前帧所有代码完成后执行
- `WaitForFixedUpdate`：`FixedUpdate` 完成后执行
- `null` / `0`：`Update` 完成后（等同于下一帧）

### `RectTransform` 与 `Transform`

`RectTransform` 可以强转为 `Transform`，反之不行。

- **锚点（Anchor）**：当前物体在父物体中的位置（0-1），父物体改变时决定子物体的大小和位置。
- **anchoredPosition**：UI 轴心点相对于锚点的偏移量（2D）。
- **Position**：UGUI 中 PosX/PosY 分别表示轴心点到锚点的水平和垂直距离。

> [!note] 注意
> `anchoredPosition` 忽略 Z 坐标，一般使用 `anchoredPosition3D` 进行设置。

### Collider 与 Trigger

- **碰撞体**：`isTrigger = false`，可调用 `OnCollisionEnter` / `OnCollisionStay` / `OnCollisionExit`。
- **触发器**：`isTrigger = true`，可调用 `OnTriggerEnter` / `OnTriggerStay` / `OnTriggerExit`。

**物体发生碰撞的必要条件：**
1. 至少一方带有 `Collider` + `Rigidbody`（或 `CharacterController`）。
2. 另一方带有 `Collider`。

**`CharacterController` 和 `Rigidbody` 的区别：**
`CharacterController` 是受到限制的 `Rigidbody`。

### `MeshRenderer` 中 `material` 和 `sharedMaterial` 的区别

- **`material`**：指向材质的一个实例副本。修改只影响当前 `MeshRenderer`，不波及其他使用相同材质的对象。多次获取会得到多个不同实例。
- **`sharedMaterial`**：指向材质的共享实例。修改会影响所有使用该材质的 `MeshRenderer`，包括存储在 Project 中的材质设置。**不推荐直接修改 `sharedMaterial`**。

### 光源类型

`DirectionalLight`（平行光）、`PointLight`（点光源）、`SpotLight`（聚光灯）、`AreaLight`（区域光）。

### FixedUpdate 与物理

`FixedUpdate` 通常用于物理更新。`Maximum Allowed Timestep` 限制了帧率下降时物理计算和 `FixedUpdate` 可使用的时间。

### 相机移动放在哪个函数

`LateUpdate`。

### 对象池

用于存放反复调用的资源（如敌人、子弹、特效等），避免频繁的实例化和销毁。

### DrawCall、Batch、SetPassCall

- **DrawCall**：CPU 通知 GPU 进行渲染的命令。
- **Batch**：渲染批次，合并渲染操作以减少 DrawCall。
- **SetPass Call**：每个 Pass 都需要 Unity 绑定一个新的着色器（切换渲染状态）。
  - 内置渲染管线：所有材质球的渲染 Pass 数量。
  - URP：5 个材质球，Shader 和关键字都相同，Shader 有 2 个 Pass，值就是 2。

### 批处理（Batching）

| 类型 | 原理 | 优点 | 缺点 |
|------|------|------|------|
| 静态批处理 | 离线合并 Mesh | 限制少 | 增加包体和运行时内存 |
| 动态批处理 | 运行时合并网格 | 自动 | 增加 CPU 消耗，顶点与材质有严格要求 |
| GPU Instancing | 切换矩阵渲染相同物体 | 性能极好 | 要求相同 Mesh |
| SRP Batcher | 常量缓冲区避免上下文切换 | 相同 Shader 不同材质可加速 | 只能用于 SRP |

详细对比见 [[Unity性能优化]]。

**静态批处理**本质是将相同材质且始终不动的 Mesh 合并为一个大 Mesh。限制：最多 64000 顶点。不减少 DrawCall 数量，但多次 DrawCall 间没有渲染状态切换，渲染 API 会缓存绘制命令。

**GPU Instancing** 要求同一网格同一材质，基于一个 Instanced Draw Call 一次性绘制多个模型。如果每帧修改 Transform，则开销高。

**SRP Batcher** 不减少 DrawCall，但通过将材质属性数据永久放入 GPU 的 CBUFFER 来减少 CPU 开销。

### 渲染管线（Pipeline）

主要步骤：本地坐标 → 视图坐标 → 背面裁剪 → 光照 → 裁剪 → 投影 → 视图变换 → 光栅化。

### 常用坐标变换

**Shader 中**：`WorldToClipPos`、`ViewToClipPos`、`ObjectToViewPos`、`WorldToViewPos`、`ObjectToWorldDir`、`WorldToObjectDir`、`ObjectToWorldNormal`

**C# 中**：`ScreenToWorldPoint`、`WorldToScreenPoint`、`ScreenToViewportPoint`、`ViewportToScreenPoint` 等

### UI 自动适应屏幕分辨率

`Canvas Scaler` 三种模式：
1. **Constant Pixel Size**：无论屏幕大小，UI 元素保持相同像素大小。
2. **Scale With Screen Size**（常用）：屏幕越大，UI 元素越大。
3. **Constant Physical Size**：UI 元素保持相同物理大小。

### Canvas 三种渲染模式

- **Overlay**：画布填满屏幕，UI 始终在最上层。使用 `Sort Order` 控制前后。
- **Screen Space Camera**：绑定 Camera，非 UI 元素可以加入。Z 轴不为 0 的元素单独渲染。
- **World Space**：世界空间中的 UI。

### Image 和 RawImage 的区别

- `Image`：只能使用 Sprite 图片，适合有操作的图片（裁剪、旋转等），可以进行合并批处理。更消耗性能。
- `RawImage`：各种形式的图片都可以，适合单独展示的图片，无法合并批处理。

### MipMap

MipMap 将贴图处理成一系列被优化过的不同尺寸图片，根据物体距摄像机的距离选择合适尺寸。用途：加快渲染速度、减少图像锯齿。代价：包体增大约 1/3。

### LOD（Level of Detail）

多层次细节。根据模型的位置和重要程度决定渲染的资源分配，降低非重要物体的面数和细节度，提高渲染效率。

### LightMap（光照贴图）

将场景中各个表面的光照信息输出到贴图上，运行时通过贴图呈现光照效果，减少实时光照计算。

### 矩阵相乘注意点

注意蠕变（误差累积）。

### 细小高速物体撞向较大物体

可能穿透，碰撞检测失败。解决方案：使用连续碰撞检测（CCD）。

## 图形学与渲染

参考：[[渲染管线理论]]、[[Unity Shader基础]]、[[Shader高级特性]]

### 顶点着色器和像素着色器的作用

**顶点着色器（Vertex Shader）**：
- 处理三维模型的顶点数据，对每个顶点进行数学运算，确定屏幕位置。
- 输入：顶点原始数据（位置、法线、纹理坐标）、常量数据（变换矩阵）。
- 输出：变换后的顶点属性（位置、颜色、纹理坐标等），会被插值并传递给像素着色器。

**像素/片元着色器（Fragment Shader）**：
- 光栅化后对每个片元进行处理，输出每个像素的最终颜色值。还可输出深度值或自定义数据（如延迟渲染）。

### GPU 工作原理

1. 顶点处理
2. 光栅化计算
3. 纹理贴图
4. 像素处理
5. 输出

### 渲染顺序（图形管线）

顶点着色器 → 曲面细分（可选） → 几何着色器（可选） → 裁剪 → 图元装配（三角形朝向剔除） → 光栅化 → 片元着色器。

### 碰撞检测

参考：[[渲染管线理论]]

- **AABB（轴对齐包围盒）**：六个面平行于坐标轴，计算简单快速，精度较低。
- **OBB（有向包围盒）**：根据物体形状和方向旋转，更精确但计算复杂。
- **球形包围盒**：用球体包围，只需比较球心距离和半径之和，计算简单。
- **分离轴定理（SAT）**：用于检测两个凸多边形之间是否有间隙。从每个多边形的边取法向量作为投影轴，检查投影是否重叠。
- **离散碰撞检测（DCD）**：只查询某一时刻是否相交。
- **连续碰撞检测（CCD）**：解决高速物体穿透问题（如子弹）。

### MipMap 的作用

当图像距离远时出现走样（锯齿），因为采样率与图片分辨率不匹配。MipMap 生成不同尺寸的相同图片，根据距离选择合适尺寸，消除锯齿。代价：包体增大约 1/3。

### Command Buffer

允许在 Unity 渲染管线中的特定阶段插入自定义渲染命令。可用于后处理效果、自定义渲染纹理等。

## 帧同步

参考：[[游戏帧同步]]

### 帧同步的基本概念

- **单机模式**：输入 → Update → 结束
- **状态同步**：服务器计算，结果返回客户端
- **帧同步**：服务器到固定时间点发送操作（无操作时发空包），客户端收到后执行 Step。客户端自己的输入不直接模拟，等待服务器广播后再模拟。

### 预测回滚（Prediction-Rollback）

当客户端比服务器快时，客户端先用本地预测模拟，收到服务器数据后进行回滚：
1. 客户端恢复到上一帧结束的状态。
2. 根据服务器输入重新模拟至当前帧。

**回滚实现方式**：
1. 手动备份还原（麻烦）
2. 反射（性能问题）
3. 代码生成（推荐）
4. `memcpy` 内存拷贝（需要内存紧凑）

### UDP 丢包处理

**客户端丢包**：服务器补发未同步的帧（发送 `sync_frameid + 1` 到最新帧）。
**服务端丢包**：影响较小，下一帧即可处理。

> [!warning] 帧同步注意事项
> 1. 不使用浮点数（`float`），使用定点数/整数。
> 2. 不建议使用多线程。
> 3. 不同客户端保证一致频率。
> 4. 随机种子相同。
> 5. 排序容器保证遍历顺序一致。
> 6. 逻辑和显示分离。
> 7. 使用补间过渡掩盖卡顿。

### 帧同步 Debug

- 帧同步：Dump 帧状态和帧执行过程（行为日志），对比两个客户端日志定位问题。
- 预测回滚：使用 `Dictionary<状态, 输入, 行为>` 存储，回滚时 Dump 到独立存储，保留最新。使用 Diff 定位。

## Lua

参考：[[Lua核心特性]]、[[XLua热补丁]]

### Table 中 pairs 和 ipairs 的区别

Lua 的 table 由**数组段**和**哈希段**两部分组成。

- `ipairs`：从索引 `[1]` 开始连续递增遍历（数组段），遇到 `nil` 即退出。
- `pairs`：遍历表中所有键值对，先输出数组段后输出哈希段，哈希段顺序取决于哈希算法。

```lua
local t = {[1]=1, 2, [3]=3, 4, [5]=5, [6]=6}
-- 数组段：{2, 4}
-- 哈希段：{[1]=1, [3]=3, [5]=5, [6]=6}

for i, v in ipairs(t) do print(i, v) end  -- 输出：1 2, 2 4, 3 3
for k, v in pairs(t) do print(k, v) end  -- 遍历所有
```

### Metatable（元表）和元方法

元表允许改变 table 的行为。常用元方法：

```lua
setmetatable(A, {
    __index = B,       -- 索引查询
    __newindex = B,    -- 索引更新
    __add = B,         -- 加法
    __call = B,        -- 执行方法调用
    __tostring = B,    -- 字符串输出
    __mode = "k",      -- 弱引用模式（k=key弱引用, v=value弱引用, kv=都是）
})
```

**`__index` 的查找逻辑**：Lua 先在当前 table 中查找，找不到时调用 `__index` 方法。如果 `__index` 指向一张表，则到该表中查找。

```lua
father = { prop1 = 2 }
father.__index = father
son = { prop2 = 1 }
setmetatable(son, father)
print(son.prop1)  -- 输出 2，通过 __index 查找到 father
```

### Lua 面向对象模拟

```lua
class = { x = 0, y = 0 }
class.__index = class

function class:new(x, y)
    local t = {}
    setmetatable(t, class)
    t.x = x
    t.y = y
    return t
end

function class:test()
    print(self.x, self.y)
end
```

- 冒号 `:` 定义了 `self` 参数，隐藏传递调用者。
- `class.__index = class` 是模拟类的关键一步。

### C# 与 Lua 交互性能

> [!warning] 关键瓶颈
> `gameObj.transform.position = pos` 十分耗费性能！

**取值过程**（`.` 取 Object）：
1. `ObjectTranslator` 将 Lua 中的 GameObject ID 转换为 C# 可辨认的 ID。
2. 通过 ID 从 Dictionary 中获取 C# 对象。
3. 在 Lua userdata 中存入新 ID，附上 metatable 才能使用 `.position`。

每次使用 `.` 都会有查找过程。对于临时对象，刚分配的 userdata 和 dictionary 索引可能被 Lua GC 回收，下次又重新分配。

### 值类型传递的性能陷阱

**最严重（避免）**：`Vector3`、`Quaternion` 等值类型和数组。涉及 Lua 类型和 C# 类型的多层转换：push 参数 → 构建 table → 返回。

**次严重**：`bool`、`string`（Non-Bittable 类型，涉及内存转换）、各种 Object。

**推荐**：`int`、`float`、`double`。

**优化策略**：
- 使用纯 Lua 实现（如 `Vector3 = {x, y, z}`）。
- 添加接受 float 参数的重载，避免传递 `Vector3`：
```csharp
void SetPos(GameObject obj, float x, float y, float z);
```
- 优先使用静函数导出，减少成员方法调用（避免 userdata 查找）。
- 频繁调用的函数参数不超过 4 个。
- 合理使用 `out` 关键字返回复杂类型。

### Lua 持有 C# 对象导致无法释放

Lua 中的 userdata 通过 Dictionary 关联 C# 对象。**只要 Lua 中的 userdata 未被 GC，C# 对象会被 Dictionary 持有引用**。常见问题：Component 被 Lua 引用后 Destroy，仍残留在 Mono 堆中。解决方案：遍历 `ObjectTranslator` 的 Dictionary 手动 nil。

### Lua 热更新原理

1. 保存 `_G` 中的老模块 table。
2. `package.loaded[module_name] = nil`。
3. 获取新模块。
4. 将旧模块 table 的值设为新模块的值。
5. 赋值到 `package.loaded[module_name]`。

`require` 会阻止多次加载相同模块，所以必须先清除缓存。

### Xlua 热更新

详细流程参见 [[XLua热补丁]]。

核心原理：
- 通过 `Mono.Cecil` 对打了 `[Hotfix]` 标签的类进行 **IL 注入**。
- 注入后，每个方法前检查是否有对应的 Lua 函数（通过 `DelegateBridge`），有则执行 Lua 逻辑，无则执行原有 C# 逻辑。

### Lua 弱引用

通过 `setmetatable(t, {__mode = "k"})` 设置弱引用键，当 key 被 GC 回收后，table 中对应项也自动移除。

| 模式 | 说明 |
|------|------|
| `"k"` | key 为弱引用 |
| `"v"` | value 为弱引用 |
| `"kv"` | key 和 value 均为弱引用 |

### Lua Table Rehash

Lua 的 table 在添加/删除元素时可能触发 **rehash**：
- 计算数组部分和哈希部分的新大小，满足：数组空间至少一半被利用，且后半部分至少有一个元素。
- **优化建议**：尽量预分配大小（`local tb = {nil, nil, nil}`），数组部分不包含 `nil`，删除元素不会立即触发 rehash。

### Lua GC（三色标记法）

1. 初始：所有对象标记为白色。
2. 标记阶段：从 root set（全局变量、当前局部变量）出发，将可达对象标记为灰色 → 逐个取出灰色，标记其可达白色对象为灰色，自身标记为黑色。
3. 清除阶段：不存在灰色对象时，清除白色对象，将黑色标记回白色。
4. 支持**增量式**标记，可随时暂停和继续。

### `rawget` 和 `rawset`

直接操作表，忽略元方法：
```lua
rawset(table, key, value)   -- 绕过 __newindex
value = rawget(table, key)  -- 绕过 __index
```

### 全局变量泛滥

配置 `_G` 的 `__newindex` 和 `__index` 进行拦截和控制。

## C++

参考：[[C++核心语法]]、[[C++并发与异步]]

### malloc 底层原理

- `malloc` 分配的是**虚拟内存**，不是物理内存。只有访问已分配的虚拟地址时，才触发**缺页中断**建立虚拟内存到物理内存的映射。
- `brk()`：将堆顶指针向高地址移动获得新空间。小于 128KB 时使用 `brk()`。
- `mmap()`：大于等于 128KB 时使用 `mmap()`。
- `malloc` 会预分配更大的空间作为**内存池**。
- **free 不会立即归还内存给 OS**：`brk()` 方式申请的内存被缓存在内存池中；`mmap()` 方式申请的才会真正归还。

### new 的多种形式

- **`operator new`**：先分配空间，然后调用构造函数（通过 `placement new` 完成）。
- **`placement new`**：在已分配的空间上构建对象，**不分配内存**。
- **`nothrow new`**：不抛出异常的 `new`。
- **`new[]`**：分配数组对象。

### 内存分区

代码区、Data 区（全局/静态变量）、BSS 区（未初始化全局变量）、堆、文件映射区（动态链接库 + `mmap`）、栈区（局部变量）、内核区。

### 段错误（Segfault）

- 访问了不存在或受保护的内存。
- 修改只读变量。
- 栈溢出。
- `new` 一次 `delete` 多次。

### 移动语义与完美转发

- **移动语义**：将对象持有的资源转移给另一个对象，使用 `std::move` 将左值转为右值。
- **完美转发**：在函数模板中保持原始参数的类型和引用属性进行转发，使用 `std::forward`。

```cpp
void process(int& x) {
    std::cout << "Lvalue process: " << x << std::endl;
}

void process(int&& x) {
    std::cout << "Rvalue process: " << x << std::endl;
}

template <typename T>
void forwardToProcess(T&& arg) {
    process(std::forward<T>(arg));
}
```

| `static_cast` | 隐式转换、上行转换，地址不变 |
| `const_cast` | 移除变量的 `const` |
| `dynamic_cast` | 向下类型转换，只能用于指针/引用，要求有虚函数 |

- **指针常量**：`int * const p` — 指向不可改变，内容可变。

### C++ 编译过程

预处理 → 编译 → 汇编 → 链接

### 内联函数（inline）

避免函数调用的开销，减少运行时间但增加代码体积（空间换时间）。

### 虚表与虚表指针

- **虚表**是一个数组，存放所有虚函数指针。如果基类虚函数未被重写，子类虚函数指针指向基类的实现；否则指向子类重写的函数。这是**动态绑定**的基础。
- **虚表**存储在只读数据段（编译器产生）。
- **虚表指针（vptr）**存放在类实例中，在构造函数执行时动态绑定。
- 构造函数不能是虚函数——调用构造函数时需要先找到 vptr，而 vptr 此时尚未初始化。

### 静态多态 vs 动态多态

- 静态多态：重载（编译时确定）。
- 动态多态：重写（运行时通过虚表确定）。

### 继承对象模型

- **单继承**：子类对象包含父类数据成员 + 自身数据成员，共用一张虚表（含新的虚函数指针）。
- **多继承**：子类中含多张虚表（每个父类独立一张 + 自身）。
- **虚继承**：通过虚基类表指针（vbptr）解决菱形继承中的重复基类问题。

### 哈希表扩容

- **负载因子**：一般设为 0.7。当占用位置超过总容量的 70% 时触发扩容。
- **扩容过程**：创建原数组 2 倍大小的新数组，将所有 Entry 重新 Hash 后放入新数组。

### STL sort 的实现

快速排序分段递归；递归过深时切换为堆排序；子序列短小时切换为插入排序。

### 常见算法速查

**最小生成树**：
- **Prim**：维护 `minDist` 数组和 `isInTree` 标记。每次找不在树中且 `minDist` 最小的节点，加入树并更新邻近节点的最小距离。
- **Kruskal**：将所有边按权排序，使用并查集判断是否在同一集合，不是则加入。

**并查集（Union-Find）**：
```cpp
int find(int u) {
    return u == father[u] ? u : father[u] = find(father[u]);
}

void uni(int x, int y) {
    int fx = find(x), fy = find(y);
    if (fx != fy) father[fx] = fy;
}
```

**拓扑排序**：不断找到入度为 0 的节点从图中删除。若图中还有节点但没有入度为 0 的节点，则图中一定有环。

**A\* 路径搜索**：`F = G + H`（G = 起点到当前位置实际步数，H = 预估到终点的步数）。优化方向：优先队列优化 OpenList；JPS 跳点搜索；增加拐点惩罚（C 参数）；HPA 分层地图。

**红黑树**：
- 性质：叶子节点和根节点一定是黑；红色节点不能连续；任意根到叶路径黑色节点数相同。
- 插入：父为黑直接插入；父红叔红则父/叔/爷颜色对调；父红叔黑则根据与爷是否共线进行旋转。
- 删除：分多种情况处理（红节点直接删、黑节点根据兄弟/侄子的颜色旋转+变色）。

**单调栈**：
- 单调递增栈（栈底大栈顶小）：找下一个较大元素。
- 单调递减栈（栈底小栈顶大）：找下一个较小元素。

## 操作系统

参考：[[操作系统基础]]

### 协程

- 线程和进程是同步机制，协程是异步机制。
- 线程是抢占式的，协程是非抢占式的（由用户管理调度）。
- 一个线程可以有多个协程。
- 协程保留上一次调用的状态。

### 进程和线程的切换

**进程切换**：1) 切换页表使用新的地址空间 → 2) 切换内核栈和硬件上下文。

**线程切换**：不需要第一步（共享进程地址空间），因此更快——TLB 不会失效，虚拟地址到物理地址的转换速度不受影响。

### 进程通信方式

管道（半双工，仅亲属进程）、信号、信号量（计数器）、消息队列（容量受限）、共享内存（需同步）、Socket。

### 死锁

**四个必要条件**：互斥、请求与保持、不剥夺、循环等待。

**破解**：
- 破除请求与保持：一次性获取所有资源。
- 破除不可剥夺：允许强行抢占。
- 破除循环等待：对资源编号，按序获取。

### 进程调度算法

先来先服务、短作业优先、最短剩余时间优先（抢占式）、时间片轮转、优先级调度。

### 虚拟内存

让程序认为拥有连续可用的内存空间。实现：分页、分段、段页式。

- **虚拟页三种状态**：未分配、未缓存（分配了但不在物理内存中）、已缓存（在物理内存中）。
- 当访问未缓存的页时触发**缺页中断**，OS 将磁盘中的页加载到物理内存。

### 页替换算法

NRU（最近未使用）、FIFO（先进先出）、第二次机会、时钟算法、LRU（最近最少使用）、NFU（最近不经常使用）、老化算法、工作集算法。

### IO 多路复用

- **select**：时间复杂度 `O(n)`，仅知道有 IO 事件但不知道是哪个流，无差别轮询，有描述符数量限制。
- **poll**：时间复杂度 `O(n)`，机制与 select 类似，去掉了描述符数量限制。
- **epoll**：时间复杂度 `O(1)`，基于事件驱动，每个事件关联到 fd，内核空间和用户空间 copy 只需一次。

### 硬链接与软链接

- **硬链接**：指向文件 inode 的指针，不重新分配 inode。删除任意一个硬链接只减少链接数，不影响实际数据。
- **软链接（符号链接）**：相当于 Windows 的快捷方式。inode 不同，存储的是原文件路径。原文件删除后软链接失效。

### 中断处理流程

保护现场 → 开中断 → 中断处理 → 关中断 → 恢复现场。

## 设计模式

参考：[[设计模式-创建型]]、[[设计模式-结构型]]、[[设计模式-行为型]]

### 双重检查锁定（Double-Checked Locking）单例

普通版本（非线程安全）：
```csharp
public sealed class Singleton
{
    private static Singleton instance = null;
    private Singleton() { }

    public static Singleton Instance
    {
        get
        {
            if (instance == null)       // 多个线程可能同时通过此处
                instance = new Singleton();
            return instance;
        }
    }
}
```

简单加锁版（线程安全但性能不佳）：
```csharp
public sealed class Singleton
{
    private static Singleton instance = null;
    private static readonly object padlock = new object();
    private Singleton() { }

    public static Singleton Instance
    {
        get
        {
            lock (padlock)
            {
                if (instance == null)
                    instance = new Singleton();
                return instance;
            }
        }
    }
}
```

双重检查锁定版（推荐）：
```csharp
public sealed class Singleton
{
    private static Singleton instance = null;
    private static readonly object padlock = new object();
    private Singleton() { }

    public static Singleton Instance
    {
        get
        {
            if (instance == null)
            {
                lock (padlock)
                {
                    if (instance == null)
                    {
                        var tmp = new Singleton();
                        // 确保实例完全初始化后再赋值给静态变量
                        System.Threading.Interlocked.Exchange(ref instance, tmp);
                    }
                }
            }
            return instance;
        }
    }
}
```

> [!note] 双重检查的作用
> 外层 `if` 避免每次都获取锁；内层 `if` 确保只有一个线程创建实例。`Interlocked.Exchange` 保证赋值是原子操作，防止指令重排导致其他线程看到未完全初始化的对象。

**泛型单例**：
```csharp
public sealed class Singleton<T> where T : class, new()
{
    private static T instance = null;
    private static readonly object padlock = new object();
    private Singleton() { }

    public static T Instance
    {
        get
        {
            if (instance == null)
            {
                lock (padlock)
                {
                    if (instance == null)
                    {
                        var tmp = Activator.CreateInstance<T>();
                        System.Threading.Interlocked.Exchange(ref instance, tmp);
                    }
                }
            }
            return instance;
        }
    }
}
```

C# 中还可使用 `Lazy<T>` 简化：
```csharp
public sealed class Singleton
{
    private static readonly Lazy<Singleton> lazy =
        new Lazy<Singleton>(() => new Singleton());
    public static Singleton Instance => lazy.Value;
    private Singleton() { }
}
```

## 网络协议

### TCP/IP 各层功能

| 层次 | 功能 | 协议 |
|------|------|------|
| 应用层 | 特定应用间的信息传输 | HTTP、FTP、SMTP |
| 传输层 | 程序之间的通信 | TCP、UDP |
| 网络层 | 路由选择和转发 | IP、ARP |
| 网络接口层 | 数据帧的实际发送和接收 | 物理层 + 数据链路层 |

### HTTPS 加密过程

- **非对称加密**（RSA、ECDSA）：用于密钥交换和身份验证。服务器持有私钥，客户端持有公钥。数字证书解决公钥传输的信任问题。
- **对称加密**（AES、3DES）：用于实际数据传输，加解密使用同一密钥，速度快。
