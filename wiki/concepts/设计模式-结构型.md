# 设计模式 — 结构型

结构型模式关注如何将类和对象组合成更大的结构。GoF 定义了七种结构型模式：适配器、桥接、组合、装饰、外观、享元、代理。

## 核心问题

类和对象的组合方式直接影响系统的灵活性、复用性和性能。结构型模式通过识别实体之间的关系来简化设计。

## 七种模式速览

| 模式 | 一句话 | C# / .NET 典型应用 |
|------|--------|-------------------|
| 适配器 | 转换接口，让不兼容类协作 | `DbDataAdapter`, 第三方库封装 |
| 桥接 | 分离抽象与实现，各自独立变化 | `Stream` + `TextReader`/`TextWriter` |
| 组合 | 树形结构，统一整体与部分 | `XmlNode`, UI 控件层级 |
| 装饰 | 递归包装，动态附加职责 | `CryptoStream`, `GZipStream`, ASP.NET 中间件 |
| 外观 | 为复杂子系统提供简单接口 | `HttpClient`（封装 HTTP 细节） |
| 享元 | 共享细粒度对象，节省内存 | `string.Intern()`, `Brushes.Red` |
| 代理 | 替身/占位符，控制对象访问 | `Lazy<T>`, gRPC stub, WCF proxy |

## 容易混淆的模式组

### 适配器 vs 桥接

- **适配器**：处理**已有**的不兼容接口。事后补救，通常不修改已有代码
- **桥接**：**预先设计**的分离，让抽象和实现各自独立演化

### 装饰 vs 代理

- **装饰**：添加行为（加密装饰器 + 压缩装饰器），客户端主动组装装饰栈。**每个装饰器都执行**
- **代理**：控制访问（缓存代理、虚拟代理），通常对客户端透明。**可能根本不允许访问**

`Stream` 装饰链（`CryptoStream` ⊃ `GZipStream` ⊃ `FileStream`）是经典的装饰器应用，`Lazy<T>` 是经典的虚拟代理。两者的类图几乎相同，但意图和生命周期管理方式不同。

### 外观 vs 中介者

- **外观**：单向简化——客户端通过外观访问子系统，外观不管理子系统内部的通信
- **中介者**：双向协调——组件之间不直接通信，通过中介者相互通知。属于[[concepts/设计模式-行为型|行为型模式]]

### 适配器 vs 外观

- **适配器**：转换**一个**对象的接口，使两个不兼容接口协作
- **外观**：为**整个子系统**提供统一的简化入口

## 组合优于继承

结构型模式的一个共同主题是**通过组合替代继承**：
- **桥接**组合两个类层次（抽象 ⇄ 实现）
- **装饰**递归组合同接口对象（装饰器栈）
- **组合模式**构成递归树（叶节点 ⊂ 容器 ⊂ 容器...）
- **代理**持有真实服务对象的引用

这是面向对象设计的核心原则——组合提供比继承更灵活的结构。

## 代理的六种变体

| 变体 | 用途 | C# 实现 |
|------|------|---------|
| 虚拟代理 | 延迟初始化重量级对象 | `Lazy<T>` |
| 保护代理 | 访问控制 | Authorization proxy |
| 远程代理 | 隐藏网络通信细节 | WCF proxy, gRPC stub |
| 日志代理 | 透明记录请求 | Logging wrapper |
| 缓存代理 | 缓存重复请求结果 | `IMemoryCache` 包装 |
| 智能引用 | 引用计数，自动释放 | `WeakReference`, 连接池 |
