# 依赖注入

依赖注入（Dependency Injection）是将具体依赖的实例化从消费类中移出、由外部注入的设计模式，是控制反转（IoC）的核心实现方式。

## 核心概念

- **动机**：解除客户类与具体实现的紧耦合，遵循 DIP（依赖倒置）和 OCP（开闭原则）
- **三种注入方式**：
  - **构造注入**（首选）：依赖显式、编译时强制、不可变
  - **Setter 注入**：适合可选依赖或已有代码改造
  - **依赖获取 / Service Locator**（反模式）：隐藏依赖、运行时错误
- **DI 容器**：通过反射+配置自动管理依赖创建、组装和生命周期
- **生命周期**：Transient（每次新建）、Singleton（全局唯一）、Scoped（每个作用域一个）
- **键控服务**（.NET 8+）：`[FromKeyedServices("name")]` 按名称解析同一接口的不同实现

## 设计模式关系

- **Strategy 模式**：DI 本质上是 Strategy 在依赖管理上的应用
- **Factory 模式**：DI 容器在内部使用 Abstract Factory 模式
- **SOLID**：DI 直接支撑 DIP 和 OCP，也间接有利于 SRP 和 ISP

## 生命周期陷阱

- Singleton 中注入 Transient → Transient 被提升为事实 Singleton
- Singleton 中注入 Scoped → ❌ 编译不通过或运行时抛出
- 循环依赖 → 重构设计，`Lazy<T>` 是临时绕过

## 键控服务示例（.NET 8+）

```csharp
// 注册
builder.Services.AddKeyedSingleton<ICache, MemoryCache>("local");
builder.Services.AddKeyedSingleton<ICache, RedisCache>("distributed");

// 消费
public class ReportService(
    [FromKeyedServices("local")] ICache localCache,
    [FromKeyedServices("distributed")] ICache distributedCache)
{
    // localCache → MemoryCache, distributedCache → RedisCache
}
```

适用场景：同一接口多种实现需要在同一作用域共存（缓存策略、支付网关、通知渠道）。
