# 操作系统基础

> [!abstract] 覆盖范围
> 操作系统核心概念：状态机模型、进程管理、线程与协程、调度算法、进程间通信、同步机制、死锁、虚拟内存、分页/分段、页替换算法、I/O 多路复用、文件系统基础。整合 CSAPP 操作系统章节、南大 OS 课程、OSTEP 和面试知识。

## 操作系统的状态机模型

### 程序即状态机

任何程序 = 状态 + 状态迁移：
- **状态**：内存和寄存器的当前值
- **初始状态**：由 `execve` 加载设置
- **状态迁移**：从 PC 取指令执行（计算 + 系统调用）

### 操作系统职责

1. 防止硬件被失控程序滥用
2. 向程序提供简单一致的硬件抽象

三大抽象：**进程**（CPU 抽象）、**虚拟内存**（内存抽象）、**文件**（I/O 抽象）。

### 应用程序模型

任何程序 = `minimal.S` = 状态机：
- 总是被 OS 加载开始（通过 `execve` 设置初始状态）
- 经历状态机执行（计算 + syscalls）
- 最终调用 `_exit()` 退出

> [!tip] strace
> `strace` 可跟踪程序的所有系统调用，是理解程序行为的利器。

### 编译器优化三板斧

1. **函数内联**：将函数调用替换为函数体本身
2. **常量传播**：编译时计算常量表达式
3. **死代码消除**：删除永远不会执行到的代码

## 进程管理

### 进程状态

```
        创建 → 就绪 (Ready)
                  ↓ 调度
               运行 (Running)
             ↙          ↘
      阻塞 (Blocked)   终止 (Terminated)
            ↓ (条件满足)
          就绪 (Ready)
```

- **阻塞**：等待外设、信号等外部事件
- **就绪**：等待 CPU 调度，非人工干预

### 上下文切换

**进程切换步骤**：
1. 保存当前进程上下文到内核栈
2. 切换到新页表（改变虚拟地址空间）
3. 恢复新进程的上下文

**线程切换**比进程切换快：无需切换页表，TLB 不失效。

> [!important] 上下文组成
> 通用寄存器、浮点寄存器、PC、栈指针、状态寄存器、内核栈、打开文件表、页表基址寄存器。

### fork 与 exec

```c
pid_t fork();    // 创建子进程，复制地址空间（写时复制）
int execve();    // 替换当前进程，不创建新进程
pid_t wait();    // 等待子进程终止，回收资源
pid_t waitpid(); // 等待特定子进程
```

**fork 返回值**：
- 父进程：返回子进程 PID
- 子进程：返回 0
- 错误：返回 -1

> [!warning] 僵尸进程
> 子进程终止但父进程未 `wait()`，子进程成为僵尸 (zombie)。占用进程表条目但不再运行。父进程终止后僵尸由 init (pid=1) 回收。

### 循环 fork 陷阱

```c
for (i = 0; i < 2; i++) {
    pids[i] = fork();
    if (pids[i] == 0) {
        printf("child %d, loop %d\n", getpid(), i);
        // 不加 break：子进程继续循环 → fork 爆炸
        break;  // 加 break：子进程退出循环
    }
}
```

### 重定向实现

```c
close(STDOUT_FILENO);
open("./output.txt", O_CREAT | O_WRONLY | O_TRUNC, 0644);
execvp("wc", args);  // wc 的输出自动重定向到 output.txt
```

原理：`close` + `open` 复用最小可用 fd → stdout (fd=1) 指向新文件。

## 线程与协程

### 线程 vs 进程

| 维度 | 进程 | 线程 |
|------|------|------|
| 地址空间 | 独立 | 共享 |
| 上下文切换 | 需切换页表 (TLB 失效) | 不需切换页表 |
| 通信 | 需 IPC 机制 | 共享内存（需同步） |
| 创建开销 | 大 | 小 |

### 线程分类

- **用户级线程**：由用户态库管理，OS 不可见，一个线程阻塞 → 整个进程阻塞
- **内核级线程**：OS 管理调度，一个线程阻塞不影响其他线程

### 协程 (Coroutine)

| 维度 | 线程 | 协程 |
|------|------|------|
| 调度方式 | 抢占式 | 非抢占式（协作式） |
| 并发模型 | 同步 | 异步 |
| 管理权 | 操作系统 | 用户程序 |
| 切换开销 | 较大（内核态） | 小（用户态） |

协程保留上一次调用的状态，同一时刻只有一个协程运行。一个线程可包含多个协程。

## 进程调度

### 调度指标

- **周转时间** = 完成时间 - 到达时间
- **响应时间** = 首次运行时间 - 到达时间

### 调度算法

| 算法 | 描述 | 特点 |
|------|------|------|
| FCFS (先来先服务) | FIFO 队列 | 短作业可能被长作业阻塞 |
| SJF (短作业优先) | 选最短作业 | 长作业可能饥饿 |
| STCF (最短剩余时间优先) | 抢占式 SJF | 按剩余时间抢占 |
| RR (时间片轮转) | 固定时间片 | 响应时间好，周转时间差 |
| 优先级调度 | 按优先级分配 CPU | 低优先级可能饥饿 |

### 多级反馈队列 (MLFQ)

MLFQ 是现代操作系统（Linux、Windows、macOS）实际使用的调度器基础。

**五条规则**：
1. 高优先级队列优先运行
2. 同优先级轮转
3. 新进程进入最高优先级
4. 用完时间额度 → 降低优先级
5. 定期将所有进程提升到最高优先级（防饥饿）

**时间片**：高优先级队列短（如 20ms），低优先级队列长（数百 ms）。
**优先级提升周期**：约每 1 秒。

> [!tip] 防止"愚弄"调度器
> 旧规则按"时间片用完"降低优先级 → 进程可在时间片用尽前主动调用 I/O 维持高优先级。新规则按**累计时间额度**降级，无论中断多少次。

### 比例份额调度

- **彩票调度**：按拥有彩票数比例分配 CPU，使用随机数选择
- **步长调度**：每个进程有步长 = 总票数 / 自身票数，选择当前"虚拟时间"最小的进程运行

## 进程同步

### 临界区 (Critical Section)

一次仅允许一个线程访问的资源。

**临界区三原则**：
1. 互斥访问
2. 有限等待（进入临界区后有限时间内退出）
3. 空闲让进（不能进入时让出 CPU，避免忙等）

### 同步机制

| 机制 | 描述 | 适用范围 |
|------|------|----------|
| **临界区** | 串行化访问代码段 | 仅限本进程内 |
| **互斥量 (Mutex)** | 只有持有者能访问资源 | 跨进程 |
| **信号量 (Semaphore)** | 计数器，支持多个并发访问；count=1 即互斥量 | 跨进程 |
| **事件 (Event)** | 通知机制，触发后继任务 | 跨进程/跨线程 |

### 死锁 (Deadlock)

**四个必要条件**：
1. 互斥：资源只能独占
2. 请求与保持：持有资源的同时请求新资源
3. 不剥夺：资源不能被强制释放
4. 循环等待：形成资源等待环

**死锁处理策略**：

| 破坏条件 | 方法 |
|----------|------|
| 请求与保持 | 一次性申请所有资源 |
| 不剥夺 | 允许强制抢占资源 |
| 循环等待 | 按编号顺序申请资源（小号先申请） |

## 进程间通信 (IPC)

| 方式 | 特点 | 限制 |
|------|------|------|
| **管道 (Pipe)** | 半双工，单向流动 | 仅限父子/兄弟进程 |
| **信号 (Signal)** | 异步通知 | 信息量小 |
| **信号量** | 计数器 | PV 操作复杂 |
| **消息队列** | 结构化消息 | 容量受系统限制 |
| **共享内存** | 最快，直接访问 | 需同步机制 |
| **Socket** | 网络通信 | 性能较低，最通用 |

## 内存管理

### 虚拟内存

**核心思想**：让每个进程认为自己独占连续的地址空间。

**直接使用物理内存的问题**：
1. 内存利用率低（碎片化）
2. 进程间不安全（无隔离）
3. 地址冲突
4. 总需求 > 物理内存时频繁换入换出

**工作机制**：
- 程序启动时仅加载部分页面
- 访问未加载页 → 缺页异常 → OS 加载
- 内存不足 → OS 页面置换

### 分页 vs 分段

| 维度 | 分页 | 分段 |
|------|------|------|
| 地址结构 | 一维 | 二维（段号 + 段内偏移） |
| 大小 | 固定（通常 4KB） | 可变 |
| 碎片 | 内部碎片 | 外部碎片 |
| 用途 | 虚拟内存核心机制 | 逻辑划分与保护 |

### 页表

页表记录每个虚拟页是否在物理内存中，以及对应的物理页号。

**多级页表**：将大页表分级存储，未使用的中间条目不需下级页表，大幅节省内存。

### TLB (快表)

TLB 是 MMU 内部的页表项缓存。进程切换时 TLB 需要刷新（除非使用 PCID 等机制），这是进程切换比线程切换慢的关键原因。

### 页替换算法

| 算法 | 描述 |
|------|------|
| NRU | 最近未使用（使用 R/M 位分类） |
| FIFO | 先进先出（Belady 异常：更多页框可能增加缺页） |
| 第二次机会 | FIFO + 检查引用位，有引用则放回队尾 |
| 时钟算法 | 第二次机会的环形实现 |
| LRU | 最近最少使用（最优但硬件实现难） |
| NFU | 不经常使用（软件模拟 LRU） |
| 老化算法 | NFU + 指数加权，近似 LRU |
| 工作集算法 | 按进程工作集大小分配页框 |

### 交换空间

物理内存满时，页面被换出到磁盘的交换空间。物理内存 + 交换空间 = 虚拟内存可用总量。

## I/O 多路复用

### 使用场景

- 处理多个文件描述符
- TCP 服务器同时处理监听套接字和已连接套接字
- 混合 TCP/UDP 服务
- 多协议服务

### select / poll / epoll

| 机制 | 时间复杂度 | 描述符限制 | 机制 |
|------|-----------|------------|------|
| **select** | O(n) | 有上限 (FD_SETSIZE) | 轮询所有 fd |
| **poll** | O(n) | 无限制 | 轮询（链表结构） |
| **epoll** | O(1) | 无限制 | 事件驱动，回调通知 |

> [!important] epoll 原理
> epoll 使用一个文件描述符管理多个描述符，将事件放入内核事件表。用户态和内核态仅需一次数据拷贝。通过 `epoll_ctl` 注册事件，`epoll_wait` 只返回就绪的 fd。

### select / poll 流程

1. 用户传入 fd 数组
2. 内核拷贝数组，遍历查询每个 fd 状态
3. 无就绪事件 → 挂起进程，直到就绪或超时
4. 有就绪 → 返回，用户仍需遍历找到就绪 fd

## 文件系统基础

### 硬链接 vs 软链接

| 维度 | 硬链接 (Hard Link) | 软链接 (Symbolic Link) |
|------|-------------------|----------------------|
| inode | **相同** inode | **不同** inode |
| 本质 | 指向同一 inode 的目录项 | 存储目标路径的快捷方式 |
| 跨文件系统 | ❌ | ✅ |
| 删除原文件 | 链接数 -1，只在链接数为 0 时删除 | 软链接失效（断链） |
| 目录 | 不支持（防循环） | 支持 |

> [!note] inode
> Linux 通过 inode 识别文件，而非文件名。每个 inode 记录文件的元数据（权限、大小、数据块位置）。删除硬链接仅减少链接计数，直到计数归零才释放 inode 和数据块。

### /proc 文件系统

`/proc` 是 Linux 内核暴露的虚拟文件系统，提供进程和系统信息。

| 路径 | 信息 |
|------|------|
| `/proc/cpuinfo` | CPU 型号、核心数 |
| `/proc/meminfo` | 内存使用概况 |
| `/proc/version` | 内核版本 |
| `/proc/uptime` | 启动时长 |
| `/proc/loadavg` | 1/5/15 分钟负载 |
| `/proc/[pid]/status` | 进程状态（PID、PPID、UID） |
| `/proc/[pid]/cmdline` | 启动命令行 |
| `/proc/[pid]/fd/` | 打开的文件描述符 |
| `/proc/[pid]/exe` | 可执行文件链接 |

### C 目录操作

```c
DIR *dirp = opendir(path);
struct dirent *entry;
while ((entry = readdir(dirp)) != NULL) {
    // entry->d_name: 文件名
    // entry->d_type: 文件类型
    // entry->d_ino:  inode 编号
}
closedir(dirp);
```

## 中断处理流程

1. **保护现场**：保存寄存器状态
2. **开中断**：允许更高级中断
3. **中断处理**：执行 ISR (Interrupt Service Routine)
4. **关中断**：禁止嵌套
5. **恢复现场**：恢复寄存器，返回被中断的流程

## 地址术语辨析

| 术语 | 含义 |
|------|------|
| **物理地址** | 内存芯片上的真实地址 |
| **逻辑地址 / 有效地址** | 段内偏移（如 `mov ax, [0x7c00]` 中的 `0x7c00`） |
| **线性地址** | 段基址 + 段内偏移（未开分页时即为物理地址） |
| **虚拟地址** | 开启分页后的线性地址，经页表转换为物理地址 |

在 x86 保护模式下：逻辑地址 →(分段)→ 线性地址 →(分页)→ 物理地址。
