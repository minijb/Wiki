# /lint — Wiki 健康检查

全面检查 Wiki 知识库的质量和完整性。

## 工作流

### 1. 全量扫描
- 列出 `wiki/` 下所有子目录（concepts/、entities/、sources/、comparisons/）中的页面
- 通过 QMD 全局搜索每个页面的被引用情况
- 读取 `wiki/index.md` 获取注册页面清单

### 2. 孤立页面检测
- 识别未在 `wiki/index.md` 中注册的 Wiki 页面
- 识别入链数为 0 的页面（无其他页面通过 `[[wikilink]]` 引用）
- 两类孤立分别报告，标注页面所在的子目录

### 3. 断链检测
- 扫描所有 `[[wikilink]]` 引用
- 检查目标页面是否存在于 `wiki/`（含子目录）或 `raw/`
- 列出所有指向不存在页面的链接，标注来源页面路径

### 4. 矛盾检测
- 对同名概念跨页面检索
- 检查是否存在定义不一致、事实矛盾的声明
- 标记需要人工裁决的矛盾点

### 5. 陈旧内容检测
- 检查每个页面的 `updated` frontmatter 字段
- 标记超过 90 天未更新的页面
- 标记引用已移动/重命名来源的页面

### 6. 交叉引用缺口
- 检查概念页面之间是否存在应有的双向链接
- 例如：`wiki/concepts/` 页面 A 提到概念 B，但未链接到 B 的专门页面
- 检查 `wiki/sources/` 摘要页与 `wiki/concepts/` 概念页之间的链接完整性

### 7. 领域结构验证

对照 CLAUDE.md `raw/ 领域扩展规则` 检查 `raw/` 目录结构：

#### 命名违规
- 扫描违反命名规范的目录名：
  - 包含大写字母或空格
  - 包含特殊字符或 Unicode
  - 使用了非标准缩写
- 报告每个违规项及其规范化名称建议

#### 深度违规
- 识别 `raw/` 下超过 2 层深度的目录（如 `raw/gamedev/rendering/shaders/`）
- 建议：晋升为独立子领域或合并到父领域

#### 过度具体的领域
- 标记仅包含 1 个源文件的目录
- 标记名称过于狭窄的目录（单工具、单技术）
- 建议合并或保留的阈值

#### CLAUDE.md 不匹配
- 比较实际目录树与 CLAUDE.md 中声明的目录树
- 报告：
  - 磁盘存在但 CLAUDE.md 未声明的目录 → 建议更新 CLAUDE.md
  - CLAUDE.md 声明但磁盘不存在的目录 → 建议创建或从 CLAUDE.md 中移除

#### 正交性检查
- 寻找名称重叠或主题相近的领域（如 `raw/tools/editor/` 和 `raw/tools/ide/`）
- 标记潜在重复供人类审查

### 8. 数据缺口分析
- 比较 `wiki/index.md` 分类与 Wiki 实际内容覆盖
- 对比 `raw/` 已摄入 vs 未摄入来源
- 建议需要补充的知识领域

### 9. 生成报告
```
## Wiki 健康报告 — YYYY-MM-DD

| 指标 | 数值 |
|------|------|
| Wiki 页面总数 | N |
| Index 注册页面 | N |
| 未注册孤立页面 | N |
| 入链为 0 的页面 | N |
| 断链数 | N |
| 矛盾声明 | N |
| 陈旧页面（>90天） | N |
| 缺失交叉引用 | N |
| 领域结构问题 | N |

### 建议操作
- [ ] ...
```

### 10. 追加日志
- 记录本次检查结果摘要到 `wiki/log.md`
- 格式：`## [YYYY-MM-DD] lint | 检查 N 页面，发现 X 问题`

## 失败处理
- QMD 不可用 → 降级为手动文件扫描（Glob + Grep），结果注明"无 QMD 辅助"
- Wiki 页面数量过大（>500）→ 分批检查，每次报告一批

## 输出
- 完整健康报告（含量化指标 + 具体问题列表 + 建议操作）
